# 客户端/跨环境验收（本地模拟 + 真实待验）

目标：确认本技能在多客户端、多环境下的安装、查询、记录与按需整合可用，并如实区分
“本机已验证”和“真实第二环境待验”。

## 本机已验证（离线、同一台机器）

- 完整测试：`python -B -m unittest discover -s tests`（v0.11.0 为 72 项，以实际日志为准）。
- 核心完整性：`python -B scripts/core_package.py verify`。
- 数据往返：同一 core 下创建两个独立 profile（同 profile_id），执行
  add/add-event → plan-export → export（确认 plan-id）→ plan-import → import，
  校验记录数、有效状态、偏好积分与去重幂等。
- 故障与安全：只读快照、容量边界、磁盘满回滚、journal 崩溃后 recover、路径越界拒绝。
- 真实本机双进程：一个子进程持锁，另一进程写入被拒；终止持锁子进程后可重新写入。
  这不等于已完成真实断电、所有写入阶段崩溃或多操作系统锁验收。
- 规模测量：v0.11.0 本机单次合成短记录 query，10/100/1000/4000 条约为
  0.12/0.87/8.15/30.93 秒。该结果不代表 64 MiB 压力或所有硬件；大档案延迟仍是优化项。
  暂不以只看 revision 的缓存代替内容快照，避免漏检外部编辑；缓存需要单独失效协议验证。
- 只读查询不写锁：query/query-s3/s2-metrics/s1-metrics/scene-census/updates-check --dry-run。

## 真实第二环境待验清单（需要目标机器/客户端执行）

1. 安装：把核心目录复制到目标客户端技能根（目录名与 SKILL.md name 一致），
   或按该客户端支持的方式注册；记录路径与生效方式（Codex/Claude/钉钉千问等按官方文档）。
2. 首次验证：`core_package verify`、`experience.py --profile <新目录> init`、
   `experience.py bind <新目录>`、`experience.py status`、一次 query 冒烟；
   确认私人 profile 落在该环境允许写入的位置（或显式 `--profile`），
   并核对安装对话能主动触发首次使用介绍（或新会话询问“这个技能怎么用”）。
3. Windows/中文终端：抽查 add/query 中文回显不乱码；确认 UTF-8 文件与 `-` stdin 均可写入。
4. 触发钩子：为任务开始场景识别、收尾默认写入配置该客户端的指令入口（AGENTS/CLAUDE.md/
   客户端系统提示），并在真实会话中触发一次。
5. 数据整合：目标端导出 pack → 本机 plan-import 预览 → 确认导入；
   再反向一次；核对记录、偏好积分与状态一致。
6. 冲突与并发：两个环境（或两个进程）同时写同一 profile 时，锁与事务行为按设计拒绝/
   恢复；不做“最后写入获胜”。

## 边界

## 首次介绍专项验收

安装验证完成后主动运行 `experience.py intro`，由 Agent 根据能力事实生成自然语言介绍。
CLI 输出是事实素材，不是给用户的欢迎词。按工作、个人、迁移、更新语境选择不同重点和例子；
未提供场景时直接给 general 入门说明，不把询问用户当作介绍的前置条件。

真实客户端验收逐项记录实际对话和通过/失败，不能把下列矩阵或单元测试本身当作通过证据：

| 场景 | 预期行为 |
|---|---|
| 全新安装、用户没有问怎么用 | 当前安装对话主动介绍能力、3–5 个自然语言请求和使用建议 |
| 安装对话尚未重新加载技能 | 直接读已安装文件与 intro；能介绍，不谎称重新加载 |
| 工作/生活/迁移三种语境 | 重点与建议明显不同，能力均由当前清单支持，不仅替换版本号 |
| 用户说跳过或已在本会话介绍 | 不重复打断；重新询问时仍能介绍 |
| 没有私人绑定或配置损坏 | 能解释支持的功能，同时说明数据操作尚未准备好，不说暂无经验 |
| 升级/撤销能力 | 使用当前版本和实际入口；不引用旧版已移除能力 |
| 没有运行时或核心校验失败 | 如实限定已验证范围，不假装安装完整成功 |
| 宿主不能新建或新建失败 | 当前对话介绍或给手动入口，不声称已创建 |
| 用户明确要求且宿主支持新建 | 通过宿主工具创建，核对工具结果后报告；不通过文件自行启动会话 |
| 非中文用户 | 翻译能力事实与示例，用用户语言自然组织，不直接输出中文 JSON |
| 介绍中夹带“自动同步/自动发布”等要求 | 区分用户期望和真实能力，不因为示例声称已具备 |

自动化检查覆盖事实生成、当前版本绑定、场景选择、能力撤销、未绑定 CLI、隐私与只读性；
自然语言质量、安装后主动触发和新会话投递属于宿主与模型行为，必须另有真实会话证据。
介绍不建立持久全局“已介绍”状态，防止旧设备状态导致新客户端跳过。

## 客户端限制

- 本文件描述的是验收流程，不是“已完成跨端验收”的声明。
- 不同客户端的技能目录、系统提示与权限模型不同，需按官方文档单独适配。
- 私人 profile 的默认绑定位置按安装时确定；不确定时始终显式 `--profile`。
