# 偏好政策兼容说明

积分机制仅用于 S1 个人经验与偏好，包括 work/personal/general 三种 scope；
S1 不是 personal scope 的同义词。普通事实记录不会自动得分，仍按真实偏好证据事件计分。
S2 防错经验与 S3 可选问题记录不计分，不适用下述晋级、差异或替换积分门槛；
S2 按证据、环境与验证结果复用，S3 按变更验证和内容审核处理。

保留 plan-a-v1：10 分晋级需确认；8 分及以上遇差异提示确认；5 分及以上永久替换需要确认。
10 分时查询列出 CONFIRM_PROMOTION，执行者经用户确认后，用 add-event 写 kind=promote，
带当前 basis、同定义与真实 confirmed_by。确认有效且无冲突才进入 long-term；该事件不增加积分。
9→10 分暂时进入待确认仍沿用原政策，不自动保持生效或伪造 explicit。新差异导致 basis 失效时重新审阅。
真实来源事件去重，多端合并后重算而不相加总分。待确认和退休条目不作为有效偏好执行。
事件确认仅代表其私人证据状态，不恢复或迁移宿主系统授权。

政策来自独立 profile 的 preferences/policy.json；更改政策需要显式兼容迁移，不能只改数字。
查询使用 experience.py query，新事件使用 add-event。程序不判断要求的语义是否相同，执行者
须结合当前明确指令、适用范围与来源核对。工作/生活的不同条件不强行合并为 general。

单端使用预期：support 类事件按独立来源计数（来源按事件 ID 去重），一台设备/一个客户端长期
重复表达不一定累加；这是防“自嗨计分”的有意设计。单端要立即生效的路径是显式偏好事件
（kind=explicit + confirmed_by 原话），登记后即进入 user-explicit 有效层，不需要 8/10 分
门槛。积分晋级主要面向多端独立来源按需整合后的重算，不把单端低频使用描述成“无法生效”。
